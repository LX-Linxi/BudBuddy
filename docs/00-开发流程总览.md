## 二、每个阶段你会学到什么

这个项目对你的价值不只是"做出一个小程序"，而是走完一遍完整链路。以下是各阶段的知识收获点：

### 阶段 0-1：产品思维
- 竞品分析怎么做才不是功能罗列（→ 找结构性空白）
- 痛点如何验证真伪（→ 有具体场景 + 现有方案缺位）
- MoSCoW 优先级法，以及**"Won't have"为什么比"Must have"更重要**
- OKR 与可证伪的目标
- 北极星指标与 AARRR 漏斗
- 埋点设计（为什么必须和功能同期上线）

### 阶段 2：设计思维
- 低保真 vs 高保真的区别与用途
- 信息架构（IA）与导航设计
- 设计系统：颜色/字号/间距 token 化
- 页面四态（加载/有数据/空/错误）
- 移动端可用性原则（触控热区、首屏信息密度）

### 阶段 3：架构能力
- 技术选型的**决策框架**（不是"哪个好"，而是"在我的约束下哪个成本最低"）
- YAGNI 与过度设计的识别
- 可迁移的代码分层（薄壳 + 纯业务逻辑 + DAO）
- 数据库建模（业务时间 vs 系统时间、索引设计）
- RAG 架构与 AI 产品的工程实践

### 阶段 4：工程规范
- Git Flow 分支模型、Conventional Commits
- Code Review 自查清单
- 小程序特有：生命周期、分包、setData 性能、组件通信
- 云函数：冷启动、超时、环境变量、流式返回
- 安全：密钥管理、越权校验、Prompt 注入防护

### 阶段 5-6：交付能力
- 测试用例怎么写（等价类 / 边界值 / 异常流）
- 灰度发布与回滚
- 小程序审核规则与常见驳回原因
- 合规：备案、类目、AI 内容标识

### 阶段 7：增长与商业
- 单位经济模型（Unit Economics）
- 付费触点设计与价格锚定
- 留存曲线分析、漏斗归因
- A/B 测试基础

## 三、我们的协作方式

每个阶段我会按这个节奏来：

1. **讲原理** —— 这一步在公司里为什么存在、解决什么问题
2. **给方法** —— 具体怎么做，有哪些标准做法
3. **出交付物** —— 产出真实的文档/代码
4. **留作业** —— 有些部分你自己做，我来 review（学习效果远好于我全写完）
5. **复盘** —— 指出常见坑和你可能踩的点

**你的角色不是旁观者。** 关键决策（比如砍哪些功能、定什么价）我给方案和依据，但由你拍板 —— 这才是产品负责人的训练。
